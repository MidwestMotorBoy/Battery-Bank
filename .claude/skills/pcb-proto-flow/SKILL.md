# An agent-driven PCB flow: map, state and gaps

This is the index for building a prototype flow out of the skills in this folder. It records what one project
(the Monolith 4S USB-PD pack, 430 parts, six layers, October to November 2026) actually did with an agent at
each step, how far each step is automated, and what is missing. Nothing built from these boards had been
powered when this was written: every electrical number in these skills is modelled.

## 1. The flow

| Step | Skill | State on this project |
|---|---|---|
| Architecture and part choice for power stages | `power-stage-design`, `battery-protection-config`, `thermal-derating` | Agent proposes, owner decides. Datasheets in the repo are the source of truth |
| Part selection, stock, drop-ins | `component-sourcing` | Agent-run with live stock lookups; owner approves each swap |
| Schematic capture | `kicad-schematic-scripting` | **Edits by script, proven by netlist diff. No schematic was drawn from nothing by script.** Symbols generated by script were the top source of wiring bugs (two swapped pins on a protector) |
| Schematic review | `schematic-design-review` | Agent-run, several passes plus a challenge round. Found the serious bugs. ERC through kicad-cli |
| Bring-up plan | `bringup-planning` | Written from the netlist before the board exists |
| Placement | `pcb-scripted-placement`, `pcb-layout/references/placement.md` | Scripted: fixed parts locked, power stages from explicit coordinates, support parts by a greedy placer with pin targets. Not automatic: the power-stage geometry and the pin targets were worked out by the agent looking at pictures |
| Power copper, Kelvin taps, ground vias | `pcb-layout`, `pcb-copper-resistance` | Drawn by script from explicit coordinates, net by net, checked by the DC solver. Not generated |
| Signal routing | `pcb-scripted-routing` | Automatic (grid A* with real DRC in the loop), then hand specs for what it could not close |
| Cleanup | `pcb-scripted-routing` sections 6 and 7 | Automatic, per net, accept-or-revert |
| Verification | `pcb-layout/references/solver-verified-layout.md`, `pcb-copper-resistance`, `pcb-loop-and-coupling-solvers`, `pcb-layout-review` | Automatic once the board's loops, paths and aggressors are listed. This is the part that made a scripted board trustworthy |
| Mechanical fit | `pcb-scripted-placement` section 1 | Automatic against the enclosure model's own checks |
| Fab files | `jlc-fab-files` | Automatic; gerbers, BOM and placement file are one set and are regenerated together |
| Tools | `kicad-tools-and-mcp` | KiCad 10 in Docker in a cloud container, or on the owner's PC |

## 2. What the comparison showed

The same circuit was routed twice: by its owner by hand (reviewed over several rounds), and from nothing by
script in about 18 hours of agent time, three versions, each run through the same solvers.

- The first scripted version was legal and clearly worse on everything that depends on where fast edges run
  (hot loops up to 60 % more inductance, gate loops 49 % more, 14 signals over 10 mV per edge against 2).
- Two solver-guided fix passes brought it level or ahead on loop inductance, copper loss, via current and
  sense-pair area, and level on coupling. It stayed behind on one thing that was decided at placement: 258 mm
  of signal track cut into a ground plane, because no lane had been kept between the two power stages.
- The owner then looked at it in KiCad for a minute and found what no solver scores: a net that wandered and
  tracks that changed width for no reason. That became the tidiness measure and the cleanup pass.

So: **rules make it legal, solvers make it work, a person's eye makes it right, and each of the three found
faults the other two could not.** A flow needs all three, in a loop, after every pass.

## 3. The schematic as the source of constraints

On this project the knowledge a placer and a router need was typed into the tools as lists and regular
expressions: which nets switch, which pads are Kelvin taps that nothing else may touch, which capacitor serves
which pin, which pads close which hot loop, which parts are fixed. That is why the tools are not turnkey. In a
flow built for automation, the schematic (symbol fields, net classes, sheet structure) should declare:

| Declaration | Used by |
|---|---|
| Net class per net, with width, clearance and via size | Router, DRC |
| Switching nets, with voltage swing and edge time | Router cost near switching copper; coupling solver aggressors |
| High-impedance or sensitive nets (feedback, thermistor, current sense, crystal) | Router keep-away; coupling solver victims |
| Kelvin pairs: the resistor, the two tap pads, the pair's nets | Placement of filters, pair routing, tap sealing, tap-error solver |
| Hot loops: supply net, return net, the switch pads, the capacitors that close the loop | Placement of capacitors, loop solver |
| Gate loops: driver pin, gate resistor, FET, return net | Gate routing, loop solver |
| Which pin each two-pin support part serves (and its rank at that pin) | Greedy placer targets |
| Current per power net at the design load | Pour sizing, via counts, DC solver cases |
| Fixed parts and their positions; height zones; keep-outs | Placement, mechanical check |
| Repeated blocks (which sheets are copies) | Place once and translate; route once and copy |
| Block boundaries and the nets that cross them | Floorplan, corridor reservation, block-first routing |

Hierarchical sheets map naturally to blocks. A sheet that is instantiated twice is a repeated block.

## 4. Order of work for a new board

1. Spec and power tree. One spec file, decisions dated.
2. Parts, with stock, before the schematic depends on them.
3. Schematic, with the declarations of section 3 as fields from the start.
4. Review the netlist (not the drawing). State and fault table. Configuration defaults.
5. Enclosure limits and fixed parts as data.
6. Floorplan picture; owner agrees.
7. Placement: reservations (fan-out bands, via sites, signal corridors), power stages, support parts.
8. Power copper and ground vias; DC solver and hot-loop solver now, while geometry is free.
9. Blocks routed and scored one at a time; then links between blocks.
10. Cleanup pass; tidiness table.
11. Full check loop. Repair. Full check loop again.
12. The owner looks at it in KiCad. Each objection becomes a rule, a cost or a check, and is written into
    the skill it belongs to.
13. Fab files as one set, labelled with the board commit they were made from.

## 5. Missing pieces, most valuable first

1. Constraints declared in the schematic and read by every tool (section 3).
2. Block-first routing with declared exits; small-group rip-up or shove (`pcb-scripted-routing` section 9).
3. Corridor reservation at placement from the list of nets that cross block boundaries.
4. Generated power copper: pours sized from current, via counts from per-via limits, instead of typed
   coordinates.
5. Generated hot-loop and gate-drive geometry, chosen from several candidates by the loop solver.
6. Pin targets derived from the schematic instead of typed.
7. Schematic capture from a description (netlist first, drawing second), with every generated symbol checked
   pin by pin against the datasheet table.
8. A measured board. Until one exists, calibrate each solver against a published figure.
9. Speed: compiled search core, nets in parallel.

## 6. Working rules that held across the whole project

- The datasheet is the source of truth; a number from memory or a search snippet is a lead.
- Reversible work is done and reported; irreversible steps (an order, a merge, a write to someone's working
  board) wait for the owner's word.
- Every result names the file and commit it was computed on. Order files, renders and reviews go stale when the
  board changes; say which board each belongs to.
- "Unchanged" and "no part moved" are claims to prove with a diff.
- After every pass: a picture and a table. A scripted layout is only ever seen through the pictures the
  script makes.
- Compare with the run before, not with a limit.
- What was not checked is listed as an open item.
